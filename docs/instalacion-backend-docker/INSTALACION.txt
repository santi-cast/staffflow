==============================================================================
StaffFlow — Backend con Docker
==============================================================================

Esta carpeta contiene la imagen Docker del backend de StaffFlow y el
fichero docker-compose.yml para levantarla con un solo comando. Pensada
para quien no quiere instalar Java ni abrir el proyecto en un IDE.

El backend arranca en el perfil "dev": base de datos H2 en memoria con
datos demo precargados, login de prueba listo para usar.


------------------------------------------------------------------------------
1. Requisitos
------------------------------------------------------------------------------

- Docker Desktop instalado (Windows, macOS) o Docker Engine + Docker
  Compose v2 (Linux). Verificar con:

      docker --version
      docker compose version

- Puerto 8080 libre en el equipo (si otra aplicacion lo esta usando,
  habra que detenerla antes).

- NO hace falta Java instalado.
- NO hace falta ningun IDE.
- ~500 MB libres en disco para la imagen (446 MB descomprimida).


------------------------------------------------------------------------------
2. Arranque
------------------------------------------------------------------------------

Desde una terminal, situarse en esta carpeta y ejecutar dos comandos:

    docker load -i staffflow-backend.tar.gz
    docker compose up

El primer comando carga la imagen del backend en Docker (solo hace
falta la primera vez; en arranques posteriores se omite).

El segundo comando levanta el container. El arranque tarda unos 5-10
segundos. Cuando aparezca el mensaje "Started StaffflowBackendApplication"
el backend esta listo.

Para que el container quede corriendo en segundo plano se puede usar:

    docker compose up -d


------------------------------------------------------------------------------
3. Acceso
------------------------------------------------------------------------------

- API REST:        http://localhost:8080/api
- Swagger UI:      http://localhost:8080/swagger-ui/index.html
- Estado salud:    http://localhost:8080/api/health

Credenciales de prueba (rol ADMIN):

    Usuario:    admin001
    Contrasena: admin1234

Otras credenciales demo:

    usu001 / user1234   (rol ENCARGADO)
    usu002 / user1234   (rol EMPLEADO)
    usu003 / user1234   (rol EMPLEADO)


------------------------------------------------------------------------------
4. Detener
------------------------------------------------------------------------------

Desde esta misma carpeta:

    docker compose down

El comando detiene y elimina el container, liberando el puerto 8080.
La imagen permanece cargada en Docker para futuros arranques.

Como el perfil "dev" usa base de datos H2 en memoria, al detener el
container se pierden los cambios realizados durante la sesion. Al
volver a ejecutar "docker compose up" los datos demo originales vuelven
a cargarse desde cero.


------------------------------------------------------------------------------
5. Notas
------------------------------------------------------------------------------

- Para conectar la aplicacion Android al backend desde otro dispositivo,
  ver las instrucciones en docs/instalacion-android/INSTALACION.txt
  (apartado "Configurar URL del backend").

- El envio de correos (endpoints de recuperacion de contrasena) requiere
  credenciales SMTP reales. Para activarlo, abrir docker-compose.yml,
  descomentar el bloque "environment:" y rellenar MAIL_USERNAME y
  MAIL_PASSWORD con una cuenta de Gmail y su App Password de 16
  caracteres. Sin estas variables los demas endpoints funcionan
  correctamente pero los envios de email fallaran en tiempo de ejecucion.

- Si "docker compose up" da error en el mapeo del puerto, comprobar que
  no hay ningun otro backend de StaffFlow corriendo en el equipo (por
  ejemplo, lanzado desde un IDE). Solo puede haber uno escuchando en el
  puerto 8080.
